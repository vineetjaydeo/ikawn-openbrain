How Domain Agents Work

Each Agent = Persona + Tools + Memory Scope

A domain agent is NOT a separate process. It's a system prompt + tool subset + memory filter that runs within the same executor. The agents/ directory holds persona files that define each agent's expertise, tone, and tool access.

Ruhi Routes, Agents Execute

When a Tier 2 task fires, Ruhi (the orchestrator) decides which agent handles it. "Analyze GA drop" → Marketing Agent. "Research competitor pricing" → R&D Agent. "Draft follow-up email to lead" → Sales Agent. The agent gets its own system prompt, relevant memories, and tool subset.

Cross-Agent Collaboration

Agents can request work from each other via Ruhi. Marketing: "I need product images for the summer campaign" → Ruhi routes to R&D (creative) → ikawn_generate tool → images back to Marketing for posting. All through the same task queue.

Enterprise Multi-Tenant

Each brand gets the same agent suite, scoped by brand_id. MaxFashion's Marketing Agent only sees MaxFashion's memories, GA data, and content. iKawn (V) gets all agents with full access. The agent definitions are shared — the data is isolated.
